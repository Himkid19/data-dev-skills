# 概念归一对照表 · 先定位业务场景，再做词根翻译

> 解决的问题：不要把 dm_mast 源表中文字段**直译**进主数据。源表字段带着源系统的具象化
> 视角（"债券名称""股票代码"），主数据的视角是**抽象对象类**（证券）。翻译前先回答：
> "这个字段在主数据标准对象类下是什么？"，再用标准概念查缓存——缓存的优先级顺序本身
> 就建立在标准概念命名上（证券基础 > 子类基础 > 普通）。

## 1. 归一流程（第 1/2 步的前置步骤，逐字段执行）

1. **识别对象类**：该字段说的是哪个标准对象？（债券→证券 var 域；股票→证券；基金→证券；
   机构→主体 pty 域……）
2. **还原特性**：剥掉具象化前缀后，特性是什么？（债券名称→"名称"特性挂在"证券"对象类上）
3. **查标准概念缓存**：用归一后的中文名（如"证券名称"）查 `roots.py cache-hit`，
   命中即复用（cache 会按 scr_base > 子类 base > common 取最优）；
4. **查不到才具象化**：若治理组参考案例已对该子类字段做过具象化决策（如"债券名称→full_name"），
   缓存命中则直接复用，**不重新推导**；
5. **都无 → 正常词根拼接**，并在字段决策备注里写明归一判断（为什么没归一/为什么具象化）。

## 2.0 子类证券维度字段：类型词强制剥离

当**本表的证券维度本身就是某个证券子类**（指数表/基金表/债券表/股票表，如"指数融资融券
交易统计"表的证券维度就是指数）时，挂在该维度上的代码/名称/简称字段**禁止保留子类类型词**
（`idx_`/`fund_`/`bnd_`/`stk_` 前缀 + 代码/名称 的字面直译），必须剥离类型词归一到**证券级
标准字段**：

| 源字段（子类表内） | 归一后中文名 | 英文名 |
|---|---|---|
| 指数代码 / 基金代码 / 债券代码 / 股票代码 | 证券代码 | scr_cd（统一证券编码口径则 scr_id） |
| 指数名称 / 基金名称 / 债券名称 / 股票名称 | 证券中文名称 | scr_cn_full_name |
| 指数简称 / 基金简称 / 债券简称 / 股票简称 | 证券中文简称 | scr_cn_abbr_name |
| 指数英文名称 / 股票英文名称 | 证券英文名称 | scr_en_name |
| 指数英文简称 / 股票英文简称 | 证券英文简称 | scr_en_abbr_name |

> **反面案例**：指数融资融券交易统计产出把「指数代码→idx_cd、
> 指数名称→idx_name」按字面直译，未剥离类型词——正确译名为
> **证券代码 scr_cd / 证券中文名称 scr_cn_full_name**。

**边界（仍保留子类词根的情形）**：

- 子类**不是**本表证券维度、而是附加维度/标的属性：如债券表里的"指数标的"仍走
  `idx_undrl_scr_cd`（§2.1-4）；
- 特性**只在子类上有意义**（§3）：如"基期""指数特征代码"这类指数特有属性保留 `idx_` 词根
  （base_date / idx_char_cd）。

## 2.1 表示类消歧：代码 / 名称 / 日期 / 标识

源字段中文名常常不带表示类后缀（"国别地区""基期"），直接拼词根会漏掉 cd/name/date
或猜错表示类。逐字段按以下优先级消歧：

1. **先看源字段英文（src_fld_en）**：源英文成分可判断表示类时按源判断，中文名同步补齐：
   - 含 `date` → 中文补"日期"、英文以 `_date` 结尾（基期 + src idx_basic_date → **基期日期**）；
   - 含 `name` → 名称类，英文带 `name`；
   - 含 `cd`/`code` → 英文以 `_cd` 结尾（编制机构代码 src comp_org_cd → **comp_co_cd**）；
   - 含 `id` → 英文以 `_id` 结尾（发布机构代码 src iss_corp_id → **iss_co_id**）。
2. **源中文带"代码/编码"必须保留**：源中文名带"代码"（或"编码"）的，目标中文保留"代码"、
   英文以 `_cd` 收尾——禁止翻译时把"代码"丢掉（指数特征代码 + src idx_char → **idx_char_cd**）。
3. **源中文、源英文都判断不了 → 默认按名称**：中文补"名称"，英文加 `_name`
   （国别地区 + src cty → **国别地区名称 cty_name**）。禁止默认成代码或裸对象名。
4. **"标的"类默认按名称**："××标的""标的证券"默认归一为
   "××标的名称"，英文 `…_undrl_name`（招标标的 → **招标标的名称 invtb_undrl_name**）；
   映射明确给出证券代码的以映射为准（指数标的 → **指数标的证券代码 idx_undrl_scr_cd**）。
5. **机构 / 企业 / 公司 统一 co**：三者一律用词根 co，禁止 org/corp/comp_org 残留
   （编制机构 → comp_co，发布机构 → iss_co）。已入固定搭配表强制覆盖旧译
   （机构→Org、企业→Corp）。

> 该批次词根口径同时依赖 `references/fixed_collocations.csv` 的**高优先级词根批次**。
> 注意：批次中的 是否→whth **不生效**——硬性门控"是否/判断类
> 统一 xx_flag"优先，是否 前缀由脚本剥离后追加 `_flag`。

## 3. 什么时候不归一（保留具象化/子类口径）

- 该特性**只在子类上有意义**：如"债券期限""票面利率""转股价"是债券特有，归一到证券反而失真
  → 保留 bnd 词根前缀（bnd_term_day_cnt、intrt_desc）。
- 各子类**口径/粒度不同**且不可合并：列入多源整合表交用户拍板（迭代场景，见 task2-mapping.md §4），不擅自归一。
- 治理组参考案例已明确具象化决策：复用案例，不翻案。

## 4. 与缓存优先级的配合

归一后查缓存的取用顺序（roots.py cache_lookup 自动执行）：

```
scr_base（证券基础信息）> stk_base / bnd_base / idx_base / fund_base（子类基础信息）
> common（普通模型）> other
```

例：源字段"债券名称"，归一为"证券中文名称"后若证券基础信息缓存已有 `scr_cn_full_name`，取 `scr_cn_full_name`；
若只有参考案例的"债券名称→full_name"（bnd_base），且归一概念无缓存，则复用 full_name 并
在备注中记录"子类具象化，待证券级缓存建立后评估迁移"。

## 5. 比值字段归一（a/b(%) → a占b比重 → a_to_b）

源表常见"a/b(%)"形态的占比/比率字段（利润表、现金流量表比值指标），**禁止整串直译**，
按三步处理：

1. **归一中文**：`a/b(%)` → 「a占b比重」（如 `所得税/利润总额(%)` → 所得税占利润总额比重）；
2. **分别翻译 a、b**：分子分母各自走正常翻译链路（固定搭配 → 白名单 → 缓存 → 词根拼接），
   遇到**词根库没有的词**：先换近义词 lookup，仍无则**与团队约定口径**后登记进
   `fixed_collocations.csv`（例：劳务→按近义词 服务serv 处理），禁止臆造；
3. **用 `to` 连接**：英文名 = `abbr(a)_to_abbr(b)`，下划线分隔。
   `to` 计入词根段数；比值字段经用户审批可超 5 段上限。

已确认案例（命中缓存直接复用，勿重拼）：

| 源字段（a/b(%)) | 归一中文 | 英文名 |
|---|---|---|
| 所得税/利润总额(%) | 所得税占利润总额比重 | tax_to_ebit |
| 价值变动净收益/利润总额(%) | 价值变动净收益占利润总额比重 | val_chg_net_yield_to_ebit（6段，用户已批准） |
| 经营活动净收益/利润总额(%) | 经营活动净收益占利润总额比重 | oper_act_net_yield_to_ebit（6段，用户已批准） |
| 销售商品提供劳务收到的现金/营业收入(%) | 销售商品提供劳务收到的现金占营业收入比重 | sal_serv_cash_to_busn_income |

配套固定搭配：利润总额→ebit、所得税→tax、销售商品提供劳务收到的现金→sal_serv_cash。

新增比值字段翻译确认后，同样回写缓存并把口径补进本节案例表。
